## 1. Executive Summary

1. **Performance is bottlenecked by SageMath backend mismatches, not algorithmic limits:** Across 13 profiled workloads (`B1`) and all 148 repository symbols (`A1`–`A6`), **>85–99% of runtime** is consumed by four structural Sage defects: (i) NTL arbitrary-precision `Polynomial_ZZ_pEX` marshaling on $\mathbb{F}_{2^m}$ (`generator_matrix` scales $O(n^3)$, `18.0 s` at `GF(256)` $k=112$); (ii) pure-Python $O(n^2)$ `lagrange_polynomial` & per-call `GRSErrorErasureDecoder` code rebuilds (`278–435 ms` at `q=256`, `7.1–16.3 s` & `42–152 MiB` at `q=1024`); (iii) uncached missing-`pbori` `LazyImport` `fstatat64` scans + `numpy.set_printoptions` on every `vector(F, ...)` call (**59–63%** of `IterativeDecoder`); and (iv) un-overridden `Matrix_gf2e_dense` matvec/vecmat + eager `matplotlib.pyplot` import (`~320–464 ms` idle) and `MultiGraph` `FancyArrowPatch` plotting (`2.5–39 s`).
2. **Immediate non-Sage quick wins deliver 10×–500× before touching dependencies:** Switching `PolynomialRing` to `implementation="generic"` (or slimming `passagemath` to `[m4rie]+brial`), replacing `vector(F, lst)` with cached `V(lst)`, exploiting Khatri–Rao/Vandermonde `generator_matrix`, sharing 1 canonical affine-equivalent local decoder, skipping redundant Stage-2 global checks when $k=k_{\max}$, vectorizing `minimum_distance_py`/`weight_distribution` in NumPy (`131×–260×` idle-verified), lazy-importing Matplotlib with `LineCollection` (`41×`), and `ProcessPoolExecutor` simulation parallelism (`~0.95·P×`) unlock huge gains immediately.
3. **SageMath dependency surface is small, yet carries severe footprint & GPL-license debt:** Only **21 `sage.*` imports** (`19` in `src/`, `2` in `tests/`), all reducible to general $\mathbb{F}_{p^m}$ arithmetic (including odd `GF(13)`, `GF(9)`, `GF(81)`, `GF(121)`, `GF(1369)`), univariate polynomials, dense RREF/kernel, and **plain Reed–Solomon** decoding on arbitrary evaluation points (including $\alpha = 0$). Yet `passagemath` costs **1.76 GiB** (`2.1 GiB` venv, 26+ wheels), **GPL-2.0+/GPLv3** (conflicting with `tamo-barg-lrc`'s **MIT** license), no native Windows wheels for `pari`/`brial`, and Python `>=3.11,<3.14` (breaking `pyproject.toml`'s `>=3.10`).
4. **Primary Recommendation — Adopt `ff_backend` Plugin Architecture + Custom MIT Hybrid Backend (Pure NumPy/LUT Core + C99/Cython $\mathbb{F}_{2^m}$ Accelerator, `4.46–4.53 / 5.00`):** Delivers **814×–9,274×** (idle-verified) RS decoding speedups, **109×–268×** `intersect_encoding_bases`, **1.21M local words/s** batched throughput, **`~68 MiB`** total footprint (`0 MiB` runtime deps beyond NumPy), **`149 ms`** import (0 ms JIT cold-start), **100% MIT** licensing, Python `>=3.10` + Windows/macOS/Linux wheels, and **4,104/4,104** bit-exact Sage parity. Keep slimmed **`passagemath-modules[m4rie]` + `passagemath-brial`** (`-48%` disk, `2×–15×` faster with 0 LOC!) as an immediate Phase-0 stopgap and permanent opt-in `[sage]` CI differential oracle.
5. **Why not `galois` or `python-flint` as primary?** `galois` (`3.55/5`) incurs **`+26.0 s`** uncached LLVM JIT on `pytest` (`3.7×` slower than Sage), pure-Python `row_reduce` (`5–50×` slower than M4RIE), an 8 ms `matmul_jit` parfor cliff, cyclic-only `ReedSolomon`, and `172 MiB` `llvmlite`. `python-flint` (`3.33/5`) is elite on L3/L4 polynomials (`46.7 ms` idle at `GF(1024)` Gao, `334 ms` at `GF(4096)`), making it a great optional `[flint]` plugin for $q \ge 4096$, but lacks `fq_default_mat` (`225×–1,690×` RREF regression vs M4RIE). All other Python libraries (`SymPy`, `pyfinite`, `reedsolo`, `komm`, `unireedsolomon`, `pyldpc`, `zfec`) are decisively rejected.

## 6. Recommendation, Target Architecture & Phased Migration Plan

### 6.1 Primary Path & Fallback Strategy

- **Primary Path (Single Recommended Decision):** Implement **B2's `ff_backend` Protocol** with a **Custom MIT Hybrid Backend (`tamo_barg_lrc._ff`)**: a **~1,040 LOC Pure-NumPy + LUT core** (covering all $\mathbb{F}_2, \mathbb{F}_{2^m}, \mathbb{F}_p, \mathbb{F}_{p^m}$ with bundled Conway polynomials) paired with a **~620 LOC portable C99 header + thin Cython extension** (`ff_core.h` + `_ff_cy.pyx`, `~297 KiB` `.so`, zero runtime deps beyond `numpy`) accelerating all $\mathbb{F}_{2^m}$ hot paths (branchless LUT mul, matvec/matmul, RREF/kernel, polynomials, unified Sugiyama+Chien+Forney EE RS decoder, batched multi-word decode, and 64-bit bit-sliced syndrome/weight enumeration). Retain slimmed **`passagemath-modules[m4rie]` + `passagemath-brial`** strictly as an **opt-in `[sage]` extra** (`importlib.metadata.entry_points`) serving as the CI differential test oracle and legacy interop layer.
- **Fallback Paths:**
  1. *No-compiler / exotic-platform fallback (built-in):* Automatically falls back to the Pure-NumPy + LUT core (`4.09/5.00`, still `12×–800×` faster than Sage on RS & `intersect`, zero build deps).
  2. *Extreme-size ($q \ge 4096$, rate-$1/2$ Gao) extension:* Optional `[flint]` plugin wrapping `python-flint` (`B4`) for L3/L4 Half-GCD + subproduct-tree operations (`46.7 ms` at `q=1024`, `334 ms` at `q=4096`) — and re-evaluate `python-flint` for L2 if upstream wraps `fq_default_mat`.
  3. *Zero-code emergency fallback:* Slimmed `passagemath` (`[m4rie]+brial`) works today with 0 code changes (`-48%` disk, `2×–15×` faster).

### 7.2 Cross-Agent Discrepancies Reconciled

1. **Swarm CPU contention on wall-clock timings (`A1`/`A2`/`A4`/`A6`/`B5` vs `B1`/`A5`/`C1`):** Because multiple agents ran concurrently on 2 vCPUs, `time.perf_counter()` medians in `A1`, `A2` (imports: `4.17 s` vs `B1`/`B2` idle `1.14 s`), `A4` (`GF(256)` init: `1,264 ms` vs `B1` `310 ms` / `B6` `306 ms` / `C1` idle `314 ms`), `A6` (`331 ms` vs `C1` `63.2 ms`), and `B5`'s Sage baseline (`636 ms` vs `C1` `278 ms`) experienced 2×–5× wall-clock inflation. `FINAL_REPORT.md` normalizes headline figures to idle / `process_time` baselines.
2. **Does `TamoBargCodeTwoSets.__init__` invoke `intersect_encoding_bases` once or twice? (`A1` vs `A4`/`B1`):** Reconciled empirically (`C1`): `TamoBargCodeTwoSets.__init__` calls `self.max_dimension()` → `self.encoder()` (populating `@cached_method` key `(None,)`). Calling `code.encoder()` hits cache (`0.002 ms`, what `A4`/`B1` measured), whereas calling `code.encoder("VectorEncoder")` explicitly misses under key `("VectorEncoder",)` and re-runs `intersect_encoding_bases` from scratch (`same_obj=False`, what `A1` measured!).
3. **Initial dependency map errors (`shared_context.md` vs `B2` AST audit):** `StaticErrorRateChannel`, `right_kernel`, `row_space().intersection`, `.polynomial()`, and `.nth_root` are **not used** anywhere in the repo; `zero_vector`, `left_kernel_matrix`, `sage.all__sagemath_modules`, and test-only `ZZ`/`QQ` were missing from the initial map.
4. **Expander graph decoder usage (`A2`):** `self._G` and `get_error_position_subgraph` are **never called** by any decoder — only eagerly built in `TamoBargCodeTwoSets.__init__` and read by `simulation/runner.py` setup.
5. **`python-flint` license score (`B4` `3.5` vs `B6` placeholder `4.5`):** Adopted `B4`'s verified `3.5 / 5.0` (MIT bindings + LGPL-3.0-or-later bundled FLINT/GMP/MPFR).
