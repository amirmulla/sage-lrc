## 2. Overall Module Design & Critique (Executive Narrative)

The simulation subsystem cleanly separates reusable orchestration (`src/tamo_barg_lrc/simulation/runner.py`), streaming post-processing (`postprocess.py`), and thin `argparse` CLI wrappers (`simulation/*.py`, 63–124 LOC each). Three Monte Carlo engines (`run_error_weight_simulation`, `run_global_threshold_simulation`, `run_decoding_success_simulation`) share a uniform setup pipeline (`_prepare_code_and_codeword` → `build_decoder` → `bipartite_graph` → `compute_expansion_metrics` → `save_bipartite_graph_plot` → `build_candidate_error_positions`) and reuse a single instantiated decoder across all trials via the `DecodeOutcome` adapter (`invoke_decoder`). A fourth engine (`run_weight_distribution_analysis`) computes exact weight spectra via `compute_code_weight_distribution`.

**Key strengths:**
1. **Decoder & codeword reuse:** Decoders are built once before the Monte Carlo loops (never reconstructed per trial), and `AbstractCode.decoder` is `@cached_method`, making repeated lookup ~0.3 µs vs 15–65 ms uncached.
2. **Low per-trial harness overhead:** With `print_log=False`, `invoke_decoder` accounts for **97.0%–99.5%** of per-trial runtime across GF(64) and GF(256); channel addition, comparison, and buffered CSV output are < 0.2% combined.
3. **True streaming post-processing:** `process_error_distribution_csv` streams `*_err.csv` in O(1) input buffer and O(`real_distance`) state memory (**48 KB peak at 100,000 rows**, 2.1M rows/s).

**Principal architectural bottlenecks & critiques:**
1. **Serial execution of embarrassingly parallel Monte Carlo loops (P0):** Default CLI runs (`sim_itr=5000..10000`, `max_err=64..250`, i.e., 320k–1.25M trials) run single-threaded at 7–56 trials/s on GF(256) (requiring **6–45 hours** single-core). All 6 Sage decoders pickle cleanly (13–35 KB) and match serial bit-for-bit after unpickling; our `ProcessPoolExecutor` + `SeedSequence` prototype achieves **1.48×–2.02×** on 2 cores (`fork` launch 134 ms) and projects to **~0.95·P×** on `P` cores.
2. **Slow Python fallback in `compute_code_weight_distribution` (P0):** `sage.libs.gap.libgap` is unavailable in this `passagemath` install (`ImportError` costs 1.02 ms on every call), forcing a pure-Python `VectorSpace.__iter__` + full `tail_vec * sub_gen` loop (`O(q^{k-1} · k · n)`). A vectorized NumPy `GF(2^m)` log/antilog + batched XOR prototype achieves **59×–582×** speed-up (exact match, computing 16.78M codewords for GF(64) `k=4` in 64.8 ms and GF(256) `k=3` in 37.3 ms).
3. **Unconditional matplotlib rendering in setup (P1):** Every simulation unconditionally calls `save_bipartite_graph_plot`, taking **666 ms (52% of setup) at GF(64)** and **2,303–2,500 ms (67%–69% of setup) at GF(256)**—half of total runtime on short runs (`cProfile`: 5.54 s / 11.20 s = 49.4%). Should be opt-in (`--plot-graph`).
4. **Double code construction when `k=None` (P1):** `_prepare_code_and_codeword` builds a full throwaway `probe = TamoBargCodeTwoSets(..., k=1)` only to call `probe.max_dimension()`, then constructs the real code from scratch—exact **2.00×** setup penalty (290 ms → 582 ms at GF(256); default in `iterative_decoding_sim.py`).
5. **Lack of statistical stopping & crash-safe CSV flushing (P1):** Loops execute fixed `sim_itr` across all `n_err` up to `max_err` with no confidence-interval stopping or saturation cutoff, and `csv.writer` never calls `res_file.flush()` after each `n_err` row (only +0.26 ms total over 250 rows to prevent losing hours of buffered results on SIGINT/OOM).
6. **Per-trial sampling & logging waste (P2):** `sample_fixed_weight_error` re-deduplicates and re-validates `candidate_positions` (`O(n)`) on every trial (10–13× slower than pre-validated `zero_template.__copy__()` + precomputed nonzero elements); `print_log=True` formats full length-`n` Sage vectors on every trial (3–9% overhead + GB-scale logs) and evaluates `correct_c == codeword` twice.
7. **Easy Sage decoupling:** The simulation layer itself uses only 5 Sage primitives (`GF`, `VectorSpace`, `zero_vector`, `random_error_vector`, `set_random_seed`, `DecodingError`), all trivially replaceable (difficulty 1–2) once the core code/decoder layer replaces Sage vectors/fields.

### 4.2 `build_decoder` / `invoke_decoder`: Reuse vs Reconstruction

- **Actual runner behavior:** All three Monte Carlo runners invoke `build_decoder` **once** before the `for n_err` loop and reuse that single decoder instance across all `E · sim_itr` trials. No per-trial decoder reconstruction occurs.
- **Caching inside Sage:** `AbstractCode.decoder` (`sage/coding/abstract_code.py`) is decorated with `@cached_method`. Calling `build_decoder` repeatedly on the same `code` with identical `(decoder_name, max_num_of_itr, erasure_start_itr)` costs **0.0003–0.0006 ms** (cache hit) vs **1.92–64.61 ms** uncached (**4,000×–215,000×** speedup).
- **Per-trial waste inside `invoke_decoder`:** Only `GlobalErasureErrorDecoder` performs avoidable per-trial work: `era_vec = zero_vector(GF(2), len(received_word))` is allocated fresh on every call (negligible today vs 379 ms GF(256) global decode, but trivially hoisted to a cached immutable zero vector). Also, `Global*` catches `ValueError` alongside `DecodingError`—narrowing to `DecodingError` (or verifying `ValueError` only comes from Sage GRS decoders) avoids masking argument errors.

### 4.3 `compute_code_weight_distribution`: Complexity & Vectorized Prototype

- **Why the fallback always runs:** In this modular `passagemath` environment, `sage.libs.gap.libgap` is not installed (`ImportError: cannot import name libgap`). Every call to `compute_code_weight_distribution` pays **1.02 ms** attempting `code.weight_distribution()` (not cached because exceptions are not cached by `@cached_method`) before entering the Python fallback.
- **Complexity of the fallback:** Projective normalization fixes the first nonzero message coordinate to `1`, visiting `N_proj = (q^k - 1) / (q - 1) = Θ(q^{k-1})` vectors instead of `q^k`. However, inside the inner loop:
  1. `for tail_vec in VectorSpace(field, tail_dim):` invokes a pure-Python generator (`sage/modules/free_module.py:2412`) that allocates a new Sage vector via `linear_combination_of_basis(v)` on every step (`30.6%` of total time in `cProfile` for GF(64), `k=3`).
  2. `cw = lead_row + tail_vec * sub_gen` performs a full `O(tail_dim · n)` vector-matrix multiply from scratch on every step instead of an `O(n)` incremental update.
  - Total complexity: **O(q^{k-1} · k · n)** time, **O(k · n)** space (vs optimal Gray-code `O(q^{k-1} · (n - k))`).
- **Verified NumPy GF(2^m) Prototype (`fast_weight_distribution_gf2m_v2` in `bench_cli_and_fast_wd.py`):**
  Exploits four mathematical/hardware facts for binary extension fields `GF(2^m)`:
  1. Characteristic-2 field addition is **bitwise XOR** on `uint8` (`q ≤ 256`) or `uint16` (`q ≤ 65536`) integer representations.
  2. RREF splits each codeword into `rank` pivot positions (whose weight equals the message Hamming weight, tracked in `O(1)`) and `n - rank` non-pivot positions.
  3. A vectorized `O(q)` log/antilog table builds all `(rank, q, n - rank)` scalar-multiplied basis rows in NumPy in < 0.2 ms.
  4. The innermost 1–2 message dimensions (`q` or `q²` vectors) are pre-expanded into a contiguous `(B, n - rank)` byte block and XORed against each outer DFS state with SIMD `^` + `np.count_nonzero(..., axis=1)` + `np.bincount`.

  - **High-dimension (`q^{k-1} > 10^9`) alternatives:** For `d_min` only, use Brouwer–Zimmermann information-set low-weight search (only enumerates low-weight messages across disjoint information sets); for full spectrum estimation, use Monte Carlo uniform message sampling or Wang–Landau / splitting importance sampling on the weight tail.

### 4.4 CSV Writing & `process_error_distribution_csv`

- All four runners open each CSV file **once** in a `with open(...)` / `ExitStack` block outside the `for n_err` loop—there is **no** per-row open/close anti-pattern.

### 4.6 Statistical Efficiency Recommendations

Current simulations allocate a rigid `sim_itr` trials uniformly across every error weight `n_err ∈ [1, max_err]`, wasting > 80% of compute on saturated regions (`p = 100%` well below threshold and `p = 0%` well above threshold) while under-resolving the steep waterfall transition region:

1. **Uncertainty Quantification (Zero Extra Compute):** Report exact **Clopper–Pearson** or **Wilson score** 95% confidence intervals `[p_lo, p_hi]` alongside `probability_of_success` in every CSV row. For `k` successes in `N` trials (`p̂ = k/N`, `z = 1.96`), Wilson half-width is:
   $$h \approx z \sqrt{\frac{\hat{p}(1-\hat{p})}{N} + \frac{z^2}{4N^2}} \Big/ \left(1 + \frac{z^2}{N}\right)$$
   At `p = 0.5`, `N = 5,000` gives `±1.39%`; at `p = 0.99`, `N = 5,000` gives `[-0.31%, +0.24%]`.
2. **Adaptive Sequential Stopping (2×–5× compute reduction):**
   - *Outer-loop saturation cutoff:* Stop incrementing `n_err` after `m` (e.g., `m = 3`) consecutive weights observe `0` successes (for `global_decoding_sim.py` default `max_err=250`, where failure saturates well below `n_err=80`, this alone eliminates **> 65% of all trials**!).
   - *Inner-loop precision stopping (audited in batches of `B = 100` trials):* Stop early at a given `n_err` once either (a) the Wilson 95% CI half-width drops below target `ε` (e.g., `ε = 0.5%`), or (b) `n_err <= (d_design - 1)//2` (guaranteed 100% success for global/two-step decoders—requires 0 Monte Carlo trials!). Note: use an anytime-valid confidence sequence (e.g. Robbins / empirical Bernstein / Clopper–Pearson with Bonferroni/alpha-spending) to prevent optional-stopping bias.
3. **Rare Failure Events (`p_fail < 10^-5`, error-floor / near-threshold regime):**
   - Standard crude Monte Carlo requires `N ≈ 100 / p_fail` trials for 10% relative standard error (**10^7 trials** at `p_fail = 10^-5` → **4+ days** even on 64 cores!).
   - **Importance Sampling (IS) / Conditional Support Sampling:** In two-set LRC iterative decoding, failures at low error weight `w` are concentrated on **small stopping/trapping configurations** (error supports lying inside small 2-regular/bipartite cycles or dense coset-intersections where `≥ t_local + 1` errors hit the same local coset). Sampling error positions from a tilted proposal `q(S)` that up-weights multi-error coset collisions (e.g., partitioning `w` errors across fewer than `w` cosets via a Dirichlet/biased-coset proposal) and weighting each trial by exact likelihood ratio `L(S) = P_uniform(S) / q(S)` reduces variance by **10^2×–10^4×** without biasing the estimator. (The existing `--biased` mode in `expander_sim.py` already hints at concentrated supports, but lacks likelihood-ratio reweighting.)
   - **Multilevel Splitting / Subset Simulation:** For fixed `w`, evolve error patterns via Markov-chain single-coordinate swaps toward larger residual error weight `w_rem(e)`, estimating `P(w_rem > t_global)` as a product of moderate conditional probabilities `∏ P(w_rem > τ_j | w_rem > τ_{j-1})`.
